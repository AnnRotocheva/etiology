# Проект: Etiology (рабочее название) — AI-First платформа технической поддержки

## Роль в этом репозитории

Ты — исполнитель (AI/Backend Engineer), реализующий уже утверждённую архитектуру.
Полная спецификация: `docs/architecture.md` — читай перед любой значимой задачей.

Архитектурные решения верхнего уровня в этом репозитории **не пересматриваются молча**.
Если в процессе кода видишь более сильное решение или противоречие — сначала озвучиваешь
и обосновываешь, не меняешь тихо.

## Жёсткое правило (от владельца проекта)

Никогда не предлагать варианты/технологии, прямо противоречащие стратегии Apliteni
(провайдер-независимость, tenant isolation, финансовая дисциплина — бережные траты,
минимальный DevOps-оверхед на одного человека) как жизнеспособные опции.

## Контекст компании

Платформа автоматизирует AoR технической поддержки Keitaro (техническая диагностика
инцидентов, формирование bug-репортов для разработки), спроектирована как кросс-юнитовый
сервис для Apliteni с самого начала (не только Keitaro).

## Ключевые зафиксированные решения по стеку

- **Event Store / Event Bus:** Postgres (LISTEN/NOTIFY + outbox) за абстрактным
  publish/subscribe интерфейсом — не Kafka, пока реально не понадобится
- **Agent runtime:** LangGraph (или аналог) + собственный Model Gateway — обязательна
  провайдер-независимость (минимум 2 AI-провайдера + open-weights fallback), никогда
  не хардкодить вызовы к одному провайдеру напрямую
- **Tenancy:** Row-Level Security в Postgres (не отдельные БД на юнита)
- **Secrets:** managed vault (не собственная реализация)
- **Хостинг:** Lessly — деплой через её MCP (staging/production, rollback, env vars).
  Приложение остаётся обычным Docker-контейнером, в коде — без проприетарных фич Lessly
- **MCP:** строим свой gateway поверх официального MCP SDK, оба режима — server
  (отдаём возможности наружу) и client (потребляем внешние MCP)

## Границы, которые нельзя нарушать в коде

- Ни у одного агента нет и не будет инструмента для выполнения команд на инфраструктуре
  клиента — только advisory-текст, клиент исполняет сам
- Diagnostic Collector выбирает серверные команды только из провалидированного каталога;
  если сценария нет в каталоге — эскалация на человека, никогда не генерировать команду свободно
- Публикация в Knowledge Base и post-mortem — только через Approval Gate (черновик агента →
  утверждение человека), не автопубликация
- Агенты не пишут и не деплоят код продукта, не управляют релизами

## v1 — текущий вертикальный срез (что строим сейчас)

Один канал → Triage Agent → Diagnostic Collector (Knowledge Base пустая/минимальная на старте)
→ Event Store. Bug Report Composer, Incident Coordination, Post-mortem, Analytics/CSAT,
MCP Gateway наружу — сознательно отложены до следующих итераций.
